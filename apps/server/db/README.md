# Migrations

Generated by drizzle-kit (`bun run db:generate`). Applied at startup via `applyMigrations(db)` (drizzle migrator) pointed at `apps/server/db/migrations`. Paths resolve relative to process cwd; run from repo root in dev.

## Before deploying the `mr_` split (migrations 0013–0015)

- These migrations cannot be rolled back: they rename ten tables to `mr_*`, move five columns from `strategy_runs` into the new `mr_runs` table, and then drop them from `strategy_runs`.
- Take a dump first:

  ```bash
  docker exec mariadb_st_prod sh -c 'exec mariadb-dump -uroot -p"$MARIADB_ROOT_PASSWORD" --single-transaction "$MARIADB_DATABASE"' > st_db-before-mr-split.sql
  ```

- If the server dies during the migration, start it again and it continues: every statement is safe to run twice, and the copy into `mr_runs` and the column drop live in separate files.
- After this change reaches `main`, the first DB-gated test run or dev-server start migrates `st_test`, so any checkout on an older commit must be rebased or have `st_test` recreated.
