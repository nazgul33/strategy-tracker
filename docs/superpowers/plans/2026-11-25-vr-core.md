# Value Rebalancing Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Value Rebalancing (VR) as a second strategy: a pure engine, `vr_*` tables, a per-cycle Telegram message from the morning job, HTTP routes under `/api/vr`, and VR screens, with fills and cash typed in by hand.

**Architecture:** VR books (shares, Pool) are computed from two histories (`vr_fills`, `vr_cash_moves`) every time; nothing is stored as running state. Each two-week cycle is one `vr_cycles` row holding V, the band and the inputs that produced them. The order ladder is never stored: it is a function of the cycle row (band, opening shares, lot sizes, budget), and what is left of it follows from the fills dated in the cycle. MR code is untouched except for three small, listed seams.

**Tech Stack:** Bun, TypeScript, Hono, drizzle-orm 0.44 (mysql2), drizzle-kit 0.30, MariaDB 11, grammY, React + Vite + Tailwind, happy-dom tests.

Rules the signatures do not carry:

- `vrBooks`: `poolCents = sum(all moves) - buyCost - fees + sellProceeds`; `netInvestedCents = sum(moves of kind open, deposit, withdraw)` (`adjust` is not invested money).
- `nextV`: `V + roundDiv(pool, g) + D`, plus the skill term for `skill`. The skill term is `(E - V) / (2 * sqrt(g))` rounded to the nearest cent, halves away from zero, computed exactly: with `a = |E - V|`, the magnitude is `(isqrt(a * a / g) + 1n) / 2n` (`isqrt` an integer square root on `bigint`, all divisions truncating), and the sign is that of `E - V`. (Corrected during review: a fixed-scale root rounded the wrong way in rare cases.) When the result is `<= 0`, return `{ vCents: <the input V>, kept: true }`.
- `vrBand`: `roundDiv(V * (1_000_000 -/+ bandPpm), 1_000_000)`.
- `buyLot(n) = max(1, ceil(n * C / ((1_000_000 - C) * (R - 1))))` and `sellLot(n) = max(1, ceil(n * C / ((1_000_000 + C) * (R - 1))))`, with `C = VR_LADDER_COVER_PPM` and `R = VR_MAX_RUNGS` (that is `ceil(3n / 203)` and `ceil(3n / 377)`).
- `buyRungs`: rung `i` (from 0) is `lot` shares at `floor(minCents / (openShares + i * lot))` cents. Walk `i` upward and stop: **before** a rung whose cost (`price * lot`) would take the running total over `min(budgetCents, poolCents)`; **after** the first rung with `price * 1_000_000 <= firstPrice * (1_000_000 - C)`; at `VR_MAX_RUNGS` rungs; at a price of 0 cents. `[]` when `openShares < 1` or `lot < 1`.
- `sellRungs`: rung `j` (from 0) is `lot` shares at `ceil(maxCents / (openShares - j * lot))` cents. Stop: **before** a rung that would leave fewer than one share (`openShares - (j + 1) * lot < 1`); **after** the first rung with `price * 1_000_000 >= firstPrice * (1_000_000 + C)`; at `VR_MAX_RUNGS` rungs. `[]` when `openShares < 2` or `lot < 1`.
- `remainingRungs(rungs, filled)`: walking the rungs in order, a rung wholly covered by `filled` is dropped, the first one partly covered keeps `shares - (what is left of filled)`, the rest are unchanged. A `filled` of 0 or less returns the rungs unchanged.
