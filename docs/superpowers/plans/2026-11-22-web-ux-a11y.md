**Behaviour to implement (decided here):**
- *Opener capture:* in render, via a lazy `useState` initializer, read `document.activeElement`. If it sits inside another open `Modal` panel (`closest('[data-modal-panel]')`), use that panel's recorded opener instead (module-level `WeakMap<Element, HTMLElement | null>`, written when a panel mounts). This makes the default-fee popup → keep prompt chain restore to the row's Confirm button. Capturing in render matters: React applies a child's `autoFocus` during commit, before any effect, so an effect would capture the dialog's own button.
- *Initial focus* (effect on mount): if focus is already inside the panel (a child's `autoFocus` ran), leave it. Otherwise focus the first focusable element inside `[data-modal-body]`; if there is none, the header `✕` button.
- *Focusable* = `a[href], button:not([disabled]), input:not([disabled]):not([type="hidden"]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])`, in document order, within the panel (the `✕` button included).
- *Tab trap* (`onKeyDown` on the overlay): Tab on the last focusable, or with focus outside the list, moves to the first; Shift+Tab on the first moves to the last; `preventDefault` only in those cases.
- *Escape* (`onKeyDown` on the overlay): when `closeOnEscape` is true (the default), `stopPropagation`, `preventDefault`, call `onClose()`; when false, do nothing (no `onClose`, focus and values untouched).
- *Restore* (effect cleanup on unmount): `if (opener && opener.isConnected) opener.focus()`; otherwise do nothing.
- Backdrop click and the `✕` button keep calling `onClose` as today.
