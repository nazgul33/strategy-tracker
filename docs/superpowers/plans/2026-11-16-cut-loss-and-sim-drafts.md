# Cut-loss, Sim Drafts, Cost-as-Percent, Cached Bars — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a per-run cut-loss stop order (live + simulated), make simulation parameters editable as drafts that are explicitly saved, show cost as a percent with an env-supplied default, and cache daily OHLC bars in the database.

**Architecture:** A fourth `OrderKind`, `stop_sell`, flows from `computeOrders` through the order table, the digest, booking's fill-matching chain, and the sim's day resolver. `sim_runs` gains a `draft` flag so a sim can be recomputed in place until it is saved. `price_history` grows to full OHLC and gains a `bar_coverage` companion so the provider is only asked for ranges never fetched. One migration (`0007`) carries every schema change. Percent↔ppm conversion stays at the web boundary.

**Tech Stack:** Bun, TypeScript, Hono, Drizzle (MariaDB), React + Vite, `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-16-cut-loss-and-sim-drafts-design.md`

## Global Constraints

- Money is bigint myriadths (1 USD = `10_000n`); cost, gaps and cut-loss are integer ppm. Never float in the money path.
- `packages/*` must never import `apps/*`.
- No source file over ~300 lines; split by responsibility.
- Every user-facing string goes in **both** `apps/web/src/i18n/en.json` and `ko.json`. `apps/web/src/catalog.test.ts` pins: identical key sets, keys sorted by `localeCompare`, identical placeholder sets per key, and **no CJK characters in `ko` values**.
- Telegram copy goes in `CATALOG` in `packages/telegram/src/i18n.ts` with both `en` and `ko`.
- Respond/comment in English only; no Hanzi or Cyrillic anywhere in source.
- `fetch` stays injectable.
- Schedules and "today" are `America/New_York` (`todayEt`).
- Migrations are generated by `bun run --cwd apps/server db:generate`, run from the repo root, never hand-written except where this plan says so.
- Commit style: `feat|fix|docs|test|refactor|chore:`.
- `cutLossPpm`: integer ppm, multiple of `1_000`, range `[0, 500_000]`; `0` = off.
- `costPpm`: integer ppm `>= 0`, multiple of `10` on every create/update path.
- `DEFAULT_COST_PERCENT` default when unset: `0.07` → `700` ppm.
- Draft sweep age: **7 days**.

## Review Focus

Five failure modes the spec implies that no task's happy path exercises. Each has a test assigned to the task that owns the code.

1. **Pre-existing `sim_runs` rows must end up `draft = 0`.** The column defaults to `true`, so a plain `ADD COLUMN` would hide every saved sim behind the drafts UI. → Task 4, migration test.
2. **Legacy close-only `price_history` rows** (written by `persistClose`) have NULL `open`/`high`/`low`. The chart route and the bar reader must tolerate them, never return them as bars, and never crash. → Task 10.
3. **A run with `cutLossPpm = 0` must plan byte-identically to today** — no `stop_sell`, no notice. Every existing run is in this state. → Task 2.
4. **A stop fill whose order was already rolled `stale`** (capture uploaded a day late) must not match that order and must fall through to the existing fallback. → Task 7.
5. **`DEFAULT_COST_PERCENT=0` means zero cost, not "unset".** A truthiness check would silently substitute 700. → Task 6.
